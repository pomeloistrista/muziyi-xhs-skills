# Muziyi 的小红书 AI 创作 Skills

把自己在小红书 AI 内容创作中反复使用的流程，整理成可复用的 Agent Skills。目前公开一个：**小红书 AI 选题入库**。

## xhs-ai-topic-intake：从分享链接到选题初筛库

收集参考笔记时，链接容易散落在聊天里；同一方向有多篇参考，也容易重复建题。这个 Skill 将分享标题整理成候选选题，检查已有记录，经用户确认后写入飞书多维表格。

**流程：分享文字 → 离线解析 → 归纳与分组 → 查重 → 人工确认 → 新增或追加参考。**

### 我做了什么

- 从个人内容创作流程中梳理需求、字段和验收边界，借助 AI 编写和迭代指令、脚本与测试。
- 将“一个选题、多篇参考”作为数据单位，保留用户指定的分组。
- 区分新增、追加、跳过和待确认冲突；语义判断由 Agent 完成，字面相似度仅提供候选。
- 将确认内容绑定到计划摘要，提交前再次查重；异常结果停止并保留部分成功回执。
- 根据实际使用，将表格升级为「选题名称／合集／选题方向／制作时机／参考笔记」。

### 示例（虚构数据）

用户：“这两篇放同一个选题：怎样挑选 Skill、去哪里找 Skill。”

| 字段 | 待确认内容 |
| --- | --- |
| 选题名称 | 如何找到适合自己的 Skill |
| 合集 | Skill |
| 选题方向 | 干货合集 |
| 制作时机 | 待判断 |
| 参考笔记 | 两篇分别保留完整链接 |

用户确认后，新建一条选题；如果已有同方向记录，则先确认是否仅追加参考。

### 边界与隐私

- 默认只理解分享标题，不声称读过图片、视频或正文，不验证标题里的效果主张。
- 不批量采集、不发布笔记、不自动排期；不删除远端记录、不修改已有记录的其他字段。
- 目标表需自行建立；不含个人飞书坐标、凭据或真实选题库快照。`target.local.json` 和运行产物已加入忽略规则。
- 本地文件锁只能防同一工作目录内的并发提交；远端提交前复查不能提供跨客户端原子事务保证。
- 仓库目前未授予开源许可证；公开可查看不等于获得任意复用授权。依赖项目遵循各自许可。
